# Visibility

What a model shows is what `main` returns ([07](07-poc-modelling-ui.md#the-editor)). Hiding a feature's result takes it out of the return, showing it puts it back, for every feature type. The open question is the UI: how a user sees what is returned without reading the code, and how they hide and show results.

## Prior art

- **Fusion** keeps visibility out of the timeline, in the Browser, a tree of components, bodies and sketches: "click the eyeball next to the Sketch or Sketches folder in the Browser Tree" (Autodesk, via search; the article answers 403 to fetches). A folder's eye doesn't reset its children: "I don't believe it forces the children to be either on or off, when clicking the lightbulb" ([Autodesk forum](https://forums.autodesk.com/t5/fusion-design-validate-document/fusion360-browser-version-does-not-allow-to-show-hide-bodies/td-p/7242570)). A consumed sketch hides itself ("Auto hide sketch on feature creation", a preference), because "in probably 80-90% of the use cases, each sketch is single-use" ([Autodesk forum](https://forums.autodesk.com/t5/fusion-360-design-validate/after-extrude-the-sketch-is-hidden-why-how-to-disable-this/td-p/7140598), via search).
- **Onshape** splits it the same way. In the Feature list, hiding is for sketches and other non-solid features: "hover next to a feature's name and click the eye icon" ([Feature and Part Lists](https://cad.onshape.com/help/Content/PartStudio/features_and_parts_lists.htm)). Solids are hidden in the Parts list at the bottom of it, because there is no one-to-one correspondence between features and parts: many features, like extrude, can produce several parts (Onshape staff, [forum](https://forum.onshape.com/discussion/9818/hidden-3d-features), via search). The Parts list has "Hide", "Hide other" and "Hide all"; "Hovering over a hidden entity in the list shows its outline in the graphics area"; a list title's eye hides all its entities; the search filter `:hidden` lists "hidden features and bodies" (same page). In the graphics area, "use the Y key to Hide. Use Shift+Y to Show", and "Show all" brings everything back ([Hide/Show](https://cad.onshape.com/help/Content/View/hide_show.htm)). Hiding is shared by everyone in the workspace, "Hide/Show is per workspace and affects all windows/users", while Isolate and Make Transparent are per user (forum posts, via search; their pages require a login).
- **SolidWorks** shows the Solid Bodies folder only for parts with several bodies, so a hidden single body leaves nothing in the tree that reminds the user of it ([Javelin](https://www.javelin-tech.com/blog/2016/08/solidworks-model-missing/)). Hidden items are greyed out in the tree.
- **Shapr3D** lists every sketch, body and plane in the Items Manager, each with "a Visibility icon that can be toggled", with bulk commands "Show Hidden Items" and "Invert All Item Visibility" ([Items Manager](https://support.shapr3d.com/hc/en-us/articles/7873936188956-Items-Manager), via search). Sketches hide themselves after an extrusion, too.
- **Plasticity** has an Outliner of objects with hide toggles and a per-session Isolate: "displaying it exclusively on the screen, while temporarily hiding all other objects", nestable ([Focus and Isolate](https://doc.plasticity.xyz/plasticity-essentials/focus-and-isolate-objects)).
- **FreeCAD** toggles visibility with the space bar or the context menu; "A hidden object shows up grayed out in the tree" ([Tree view](https://wiki.freecadweb.org/Tree_view)). A clickable eye in the tree is requested in [#12341](https://github.com/FreeCAD/FreeCAD/issues/12341).
- **Code CAD:** OpenSCAD marks visibility in the code with modifiers: `*` disables a subtree, `!` shows only it, `%` draws it transparent without using it ([cheat sheet](https://openscad.org/cheatsheet/)). OCP CAD Viewer for CadQuery and build123d shows what `show()` was given as a tree with checkboxes, which only change the viewer ([vscode-ocp-cad-viewer](https://github.com/bernhard-42/vscode-ocp-cad-viewer)).

## Conclusions

- **Visibility belongs to results, not to history.** Every GUI tool above has a list of objects (Browser, Parts list, Items Manager, Outliner) next to its history, and solids are hidden there. Our editor has only the timeline. The return statement is our list of objects, and it has no UI yet.
- **Ours is shared and part of the model.** The return is code: it syncs, it is versioned, and it is what the model gives to whoever runs it. Onshape's shared hiding is the closest match. A per-user Isolate would be [view state](10-view-state.md), a separate feature.
- **A returned value is a feature's result, not a body.** In `plate → bore → fillet1` the three are versions of one body. Returning `bore` as well as `fillet1` shows both, on top of each other. That is why Onshape doesn't hide solids per feature. An eye on any timeline entry therefore means "show this version too". The list of results is where "hide this body" lives.
- **An entry is in one of three states:** shown (returned), consumed (a later feature carries it on) or dropped (neither; already greyed out as unused). Discoverability needs the shown state visible at all times, not only on hover as Onshape's eye is. Fusion's eye, crossed out or not, is hard to tell apart, users report (via search).
- **Peeking already works:** hovering an entry whose result isn't shown draws that result ([12](12-hover-highlighting.md#design)), as Onshape outlines a hovered hidden part.

## UX ideas

1. **The return as the last timeline entry, "Result":** a chip after the last feature that lists what shows, e.g. `⏹ fillet1, sketch3`. It works like a feature: hovering highlights each result, and clicking it opens a dialog with one row per chain end (the final body of each chain, and each unused sketch), each with an eye. It is the counterpart of Onshape's Parts list and of the return statement in the code. The dialog also lists dropped results, and could offer "Show all".
2. **Marks on timeline entries:** an eye on returned entries, always visible; a context-menu item "Show" / "Hide" on every entry. For a consumed entry, "Show" adds that version, which the dialog should say, since it overlaps the later version.
3. **In the 3D view:** a context menu on a face or edge with "Hide <body>", and a key like Onshape's Y; "Show all" in the menu of empty space.
4. **A status bar summary:** "Shows fillet1, sketch3 · 1 unused", which opens the Result dialog.
5. **Isolate, per user:** later, as view state.

Ideas 1 and 2 together cover both questions: the Result entry answers "what is returned?" in one place, the marks show it in the timeline.
