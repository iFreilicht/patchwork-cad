# One Selection

The editor's browser, timeline, code pane and dialogs share one selection: the item whose dialog is open. A click on any item selects it and opens its dialog, every pane scrolls to what stands for it, and the dialog closes as easily as it opens. Status: implemented ([Implementation](#implementation)).

## Prior art

- **Fusion** edits on a double click: "Double-click the feature you want to edit" or "right-click it and select Edit Feature" ([Autodesk](https://help.autodesk.com/view/fusion360/ENU/?guid=ASM-USE-TIMELINE)). A single click selects; on a selected feature, a double click deselects instead and "the Edit Feature window does not open" ([Autodesk Community](https://forums.autodesk.com/t5/fusion-support-forum/timeline-double-click-won-t-edit-feature/td-p/7769605)).
- **Onshape** also opens a dialog on a double click: "you can double click on it in the feature list (or right click and click 'edit')" ([forum](https://forum.onshape.com/discussion/8356/feature-dialogue-box-disappeared)). Selection cross-highlights: "selecting a face or part in the graphics area also cross-highlights associated features" ([help](https://cad.onshape.com/help/Content/feature_list.htm)).
- **Zoo Design Studio** keeps code and feature tree "1:1" ([roadmap](https://zoo.dev/roadmap)), shows "a strong link […] between the 3d-scene and the code from hovering and cursor position" ([blog](https://zoo.dev/blog/why-modeling-app)), and "You can double click feature tree items to edit their parameters" (in-app onboarding).
- **OpenSCAD** jumps from the view to the code: "Add jump to source code from 3D preview", a right-click menu of the call trace under the pointer ([release notes](https://github.com/openscad/openscad/blob/master/RELEASE_NOTES.md)).

All of them open dialogs with a double click; we open them with a single one, since our dialogs apply edits as they are made and have no OK or Cancel that a stray click could start.

## The selection

At most one item is selected per tab, and its dialog is the one in the dialog area. Every item that can be selected has a dialog, so that a selection always shows what is selected and how to close it. It is named by what survives edits of the code: a feature or Custom Script by an Automerge cursor at the start of its code, with the variable name, or a Custom Script's place in the timeline, as a fallback for when the whole text is replaced ([`state.ts`](../src/cad/src/components/editor/state.ts)); a view or configuration by its id; a document by its URL without heads and the type it is imported with, so that pinning or following it keeps it selected ([21](21-embedding.md#the-documents-list)). A pending insert, a document dropped, pasted or given to "Insert" that waits for its role ([21](21-embedding.md#dropping-pasting-inserting)), names nothing in the model yet: it is named by a number of the tab's, isn't shared through presence and doesn't survive a reload; once a role is chosen, what the role made is selected, for Import the document's row. Renaming a feature, in the code or in place, therefore keeps it selected: the dialog stays and only its label changes, without closing and opening again, and a test checks this for every keystroke of a rename typed in the code. Only when the item is deleted, e.g. by a collaborator, is the selection cleared. While a dialog's field picks ([07](07-poc-modelling-ui.md#the-editor)), clicks in the browser, timeline and view pick, and don't select.

Choosing a configuration in the Parameters dialog selects its row, so the browser and the dialog never disagree. Clicking a row double-clicked to rename it opens its dialog with the first click, which is harmless, and its second click doesn't close it again; rename stays in place on the row (double click, F2, context menu), without Fusion's select-then-click. A Custom Script or a `body()` has no form ([11](11-adopting-shapes.md#body)); its dialog has "Edit code", which opens the code pane at its code, and "Delete", which, refused, leaves the dialog open with why in the status bar.

**A view's dialog** has the view's name in its header, "Update to current view" and "Delete"; Home's has "Update to current view" and "Reset to default" ([18](18-named-views.md#home)). The grip stays on the row, where a drag starts.

Clicking a face or edge in the view selects it for its name in the status bar ([12](12-hover-highlighting.md#design)); that geometry selection stays separate from the item selection, and like any click in the view it closes the dialog ([Closing](#closing)). A face's context menu offers "Edit ‹feature›" for the feature that created it, the base of its name ([12](12-hover-highlighting.md#design)), which selects that feature. Edges get no such entry: an edge lies between faces that different features may have created, so it doesn't name one feature, and a feature that formed an edge always created a face along it, which is the more obvious thing to click.

**Presence shares the selection** ([13](13-collaboration.md)): a collaborator's selected item is marked in their colour wherever it shows, its browser rows, its timeline entry and its code, also when it is a view, a configuration, a Custom Script or the parameters entry. So it is clear who is where, whichever pane one looks at.

## Following the selection

A selection made in one pane scrolls the others to it, `nearest`, so nothing moves that is already visible: the browser to its rows, the timeline to its entry, the code pane, if open, to its code, without moving the cursor. The pane it was made in doesn't scroll. Opening the code pane scrolls to the selection's code. Hover doesn't scroll; it cross-highlights ([12](12-hover-highlighting.md#design)).

## The code pane

The selection follows the cursor at once while the code pane has focus: entering a feature's statement selects the feature and opens its dialog, entering `defaultParams`, `main`'s head or a derived value the parameters entry, a Custom Script's lines the script, the import of a document that document. Blanks before and after a statement on its lines count as the statement. Feedback without delay shows which form edits which code, the relation the editor is about ([07](07-poc-modelling-ui.md#text-vs-ast-editing)); a dialog costs less than the ghost meshes hovering already requests ([12](12-hover-highlighting.md#design)). Where there is no item, e.g. imports of the feature library or blank lines between statements, the selection is cleared, so a click there closes the dialog as a click elsewhere does.

- **Focus stays in the code.** The dialog opens beside it, and typing goes on; a field's edit splices the code under the cursor as a collaborator's would.
- **While the code doesn't parse,** e.g. halfway through typing a new name, the dialog stays, disabled, instead of closing until the code parses again. The cursor doesn't move the selection then, but a click in the timeline, which shows the last parsed state, does.
- **The code and code + preview tools** have no dialogs and stay as they are ([composable tools](07-poc-modelling-ui.md#two-tools)).

## Closing

- the × in the dialog's header;
- **Escape,** unless something uses it first: a field that was changed restores its value ([07](07-poc-modelling-ui.md#the-editor)), a rename field cancels, a menu or comment popover closes, and a field that picks stops picking;
- **clicking the selected item again;** a selected view's row first goes back to the view if the camera has left it, which is what the row is for ([18](18-named-views.md#in-the-editor));
- **a click elsewhere:** in the view, on empty space in the browser or timeline, or on code without an item. A press counts as a click if it moves less than 4 pixels, the ViewCube's threshold ([18](18-named-views.md#in-the-editor)); a drag orbits or pans and keeps the dialog, as the wheel does. Controls elsewhere, e.g. the toolbar or the status bar's Copy, do what they do; a toolbar button that adds a feature selects the new one. A click that closes an open menu or comment popover closes only that.

A field with text that isn't one expression drops it when the dialog closes, as it does when the field is left.

## Implementation

A `selection` signal in the editor state ([`state.ts`](../src/cad/src/components/editor/state.ts)), `{ kind: "feature" | "script" | "params" | "configuration" | "return" | "view" | "document" | "insert"; id: string; from: "browser" | "timeline" | "code" | "view" | "dialog" | "toolbar" }`, is the only open state of the dialogs; `editor.open()`, the selected feature with a dialog, is derived from it, and so is `selectedIndex()`, the selected timeline entry, which keeps its last value while the code doesn't parse. A `body()` is a feature without a form: it and a Custom Script get the code's dialog (`CodeDialog` in [`FeatureDialog.tsx`](../src/cad/src/components/editor/FeatureDialog.tsx)), and a deletion closes the selection only once it is done. An entry is anchored by an Automerge cursor at the start of its code (a feature's call), with its name, or a Custom Script's index, as the fallback when the cursor is lost or the code doesn't parse; an effect re-anchors it once the code parses and clears the selection when its item is gone, also for a deleted view or configuration or a document no longer imported. An edit that changes a document's id, its As or a replaced document, selects the new id in the same batch. Selecting a configuration also sets the shown one ([17](17-parameters.md#configurations-in-the-dialog)), and a shown configuration changed elsewhere, e.g. in the dialog, moves a configuration's selection along; selecting a view moves the camera ([`Browser.tsx`](../src/cad/src/components/editor/Browser.tsx), which also has the view's dialog). The browser, the timeline and the code pane each scroll to a new selection unless `from` is that pane; the code pane through a `reveal` span that changes only with the selection, so others' edits don't scroll it. Presence sends `{ kind, id }` ([`WysiwygEditor.tsx`](../src/cad/src/components/editor/WysiwygEditor.tsx)), an entry's id being its cursor, which every peer of the document resolves, and nothing for a pending insert, whose document waits in the inserts' own state ([`inserts.ts`](../src/cad/src/components/editor/inserts.ts)); the code pane underlines collaborators' items in their colour. The click-elsewhere rule is one capturing `pointerdown`/`pointerup` pair on the document, registered before any menu's, so that it sees whether a press closes a menu or popover; the lanes beneath the timeline report a click on no lane themselves. A face's context menu is a right click that doesn't move, since a right drag pans. A dialog gets the last open item, not `<Match>`'s accessor: Chrome blurs a focused field when its dialog is removed, and the field's blur handler would read the item after the Match switched.

Tested by [`cad-selection`](../src/harness/e2e/tests/cad-selection.spec.ts) in Chromium, Firefox and WebKit: each pane pair each way with the target scrolled out of view first, and the pane the selection was made in staying put; closing by each means, a menu closed alone, orbiting with a dialog open; the cursor moving through every line of M1; renaming a selected feature key by key in the code, in the timeline and in the browser without the dialog closing; "Edit ‹feature›" on a face; picking a body while a field picks; views' and configurations' dialogs; collaborators' selections and a feature renamed and deleted by one; a Custom Script's dialog with a refused deletion, replaced text and code that doesn't parse. A document's selection is tested by [`cad-documents`](../src/harness/e2e/tests/cad-documents.spec.ts), a pending insert's by [`cad-inserts`](../src/harness/e2e/tests/cad-inserts.spec.ts).

## Open

- **Many collaborators'** selections may feel distracting; the PoC marks them all.
- **Touch** is left until touch interactions are designed as a whole ([11](11-adopting-shapes.md#touch)); there, a tap would select, and the view's drag threshold would decide between closing and orbiting.
